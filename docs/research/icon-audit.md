# Ultra Tasks icon audit

Status: Proposed edits; application UI unchanged.
Snapshot: 2026-11-05, source commit `34e80b136852cddcc2e37f72f47791ffbbaad4b6`.
Tracking: User-requested UI/UX audit; no issue supplied. This is a research snapshot, not a product specification.

[Open the searchable visual audit](icon-audit.html) · [All icons with recommendations (CSV)](icon-audit/catalog.csv) · [Every static reference (CSV)](icon-audit/occurrences.csv) · [Dynamic bindings (CSV)](icon-audit/dynamic-bindings.csv)

The main problem is inconsistent meaning, rather than the underlying icon family. Ultra Tasks already uses Material Symbols Outlined plus branded/custom SVGs and native assets. Keep that family and give each common concept one consistent symbol. Keep text where a symbol cannot communicate the exact meaning—especially Tomorrow, Next week, Habits, and context-specific timer controls.

## Highest-value changes

| Priority | Current behavior                                                                                                 | Recommended edit                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | Today is a sun in navigation, task actions, date picker, notes and native shortcuts                              | Use `today` consistently; native calendar equivalents on Android/iOS. Preserve deliberate custom user icons.                                 |
| P1       | Tomorrow is twilight; Next week resembles a briefcase; Next month is a moon                                      | Use `event_upcoming`, `date_range`, `calendar_month`, always with the date label.                                                            |
| P1       | Calendar grid hides today's day number and substitutes a sun                                                     | Restore the numeral and a current-day outline; keep selection a separate state.                                                              |
| P1       | Remove from Today shows `timer_off`; reset break timer also shows `timer_off`                                    | Use `event_busy` for unscheduling; `restart_alt` for resetting a timer.                                                                      |
| P1       | Private notes use chat bubbles; Markdown source/preview toggle uses locks                                        | Use `description` for notes; `code` / `visibility` for source/preview. Keep locks for actual security.                                       |
| P1       | Backup export uses upload icon; file import uses download; copying worklog uses paste                            | Use `download` for file export, `upload` for file import, `content_copy` for copy. Remote upload/download retain their actual direction.     |
| P1       | Ordinary task deletion looks permanent; some destructive text removal looks like hiding                          | Use `delete` for recoverable task deletion; reserve `delete_forever` for permanent deletion; use `delete` when text really is discarded.     |
| P1       | Generic task schedule field can show `alarm` even without a reminder; timed deadline switches from flag to alarm | Use calendar/clock for planned date/time; keep `flag` for deadlines and `alarm` for actual reminders.                                        |
| P1       | Icon-only controls lack an explicit accessible name, or use a clickable mat-icon without button behavior         | Add translated action names, keyboard-operable buttons, and selected/expanded state. A tooltip alone is insufficient.                        |
| P2       | Issues panel uses `webhook`; Schedule route uses a clock                                                         | Use `assignment` for imported issues and `calendar_view_week` for Schedule; preserve `schedule` for an actual time value.                    |
| P2       | Generic total-task count uses a completed-task check                                                             | Use `checklist` for all tasks; reserve completion checks for completed counts/state.                                                         |
| P2       | Boards/Habits/Donate, grouping, counters and plugin identities have less direct metaphors                        | Apply the contextual suggestions below only as a coordinated pass; retain visible names. These involve more judgment than the P1 mismatches. |

P1 fixes a misleading meaning, opposite action, or access problem. P2 is consistency or optional refinement. “Keep” means the current metaphor fits that use; it does not certify its final rendered size/contrast. Do not replace a glyph globally: the same icon can be correct for one action and wrong for another.

## Canonical meanings to use when editing

| Meaning                                         | Preferred icon                                        | Rule                                                                                                            |
| ----------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Today                                           | `today`                                               | Calendar-day identity at every hour.                                                                            |
| Generic date / choose date                      | `calendar_month`                                      | Keep formatted date visible.                                                                                    |
| Tomorrow / upcoming                             | `event_upcoming`                                      | Tomorrow text is required; glyph alone is not precise.                                                          |
| Week / next week                                | `date_range`                                          | Keep Next week text; do not imply an exact range without it.                                                    |
| Planner / timed Schedule view                   | `edit_calendar` / `calendar_view_week`                | Editing plan versus visual time blocks.                                                                         |
| Time of day / elapsed duration / estimate       | `schedule` / `timer` / `hourglass_empty`              | Separate three time concepts.                                                                                   |
| Reminder / deadline / recurrence                | `alarm` / `flag` / `repeat`                           | Alert versus due-by constraint versus repeated task.                                                            |
| Remove scheduled date                           | `event_busy`                                          | Does not mean stop tracking, delete task, or remove deadline.                                                   |
| Notes / issues                                  | `description` / `assignment`                          | Documents versus imported external tasks. Actual feedback/chat keeps bubbles.                                   |
| All tasks / completion                          | `checklist` / check mark                              | Total is not the same as completed.                                                                             |
| Source / preview / split                        | `code` / `visibility` / `vertical_split`              | No photo/security metaphor for Markdown viewing modes.                                                          |
| File import / file download / copy              | `upload` / `download` / `content_copy`                | Follow actual destination and handler; export-options dialogs may use `ios_share`.                              |
| Recoverable delete / permanent delete / archive | `delete` / `delete_forever` / `archive`               | Preserve the lifecycle distinction; recover archive with `unarchive`.                                           |
| More actions / view options / reset             | `more_vert` / `tune` / `restart_alt`                  | Menu versus presentation controls versus reset.                                                                 |
| Boards / Habits / Donate                        | `view_kanban` / `event_repeat` / `volunteer_activism` | P2 choices, always labeled; coordinate settings/onboarding/nav. Habits still has no universally obvious symbol. |

## Coverage and interpretation

The scan covers 2,540 production source/configuration files and records **1,170 static references across 323 family-qualified identifiers/assets**: 239 Material symbols, 43 SVG identities, 17 Doc Mode inline SVG names, 11 Android drawables, 9 custom-SVG component groups, 3 iOS SF Symbols, and 1 image identity. References are deduplicated by source path, line, family and identifier. A component group can contain multiple SVG shapes. Asset registrations and development-only plugin references are included and labeled; these numbers are not a count of distinct visible actions or simultaneous on-screen glyphs.

The **278 dynamic bindings** include reusable slots, derived state and user/plugin values. Project, tag and counter icons can be user-selected Material names or emoji; third-party plugins and themes can introduce more. A finite source list cannot enumerate every possible runtime choice. The picker has **3,798 selectable names**, which are available choices, not 3,798 icons deployed throughout the UI.

Each table below identifies the current icon, its actual use, the edit decision and source. [The catalog CSV](icon-audit/catalog.csv) joins every scanned identity to those contextual decisions and all its source locations. [The occurrence CSV](icon-audit/occurrences.csv) includes surrounding code and extraction type. [The JSON inventory](icon-audit/inventory.json) retains groupings/scopes. [Unverified literal candidates](icon-audit/literal-candidates.csv) are an explicit review backlog: ordinary strings such as sort or list can also be icon names, so they are not counted as usages.

This is a source-based semantic/accessibility audit, not a complete rendered desktop/mobile or screen-reader test. Font availability was checked directly against the bundled font's GSUB ligatures. Proposed native/custom SVG redraws still need platform rendering checks. No app behavior, saved state, sync schema, or icon choice was changed.

### Accessibility and implementation notes

- Main nav labels are enabled by default (`showLabels: true` in `magic-nav-config.service.ts:353`); retain them. Mobile bottom nav renders icons with accessible names but no visible labels, so users unfamiliar with icons still have to guess (`mobile-bottom-nav.component.html:1`). Recommend persistent short labels for Today, Planner, Panels and Menu; at minimum test first-use recognition on mobile.
- Desktop panel buttons and Add task header button rely on tooltips without explicit `aria-label` in their templates. Material tooltips describe elements and should not be assumed to give the icon-only button its accessible name. Add explicit localized labels and `aria-pressed` to panel toggles (`desktop-panel-buttons.component.ts:23,35,49`; header template:81).
- New-board tab has no textual tab label or explicit accessible name (`boards.component.html:36`). Add “Add board”.
- Tag chips can be rendered with hidden titles and just a color circle; add an accessible tag name or a label glyph plus tooltip (`tag.component.html:25`; search-page:63).
- In the same audit, distinguish unchanged user custom icons from legacy shipped defaults: Today is persisted as a Tag and its icon may already exist in user state. Editing `TODAY_TAG.icon` alone updates new/default state, not necessarily existing installations. Decide a narrow legacy-default presentation mapping for `wb_sunny` while preserving custom emoji/icons; do not rewrite all user icon fields or change sync contracts for a visual audit.
- Centralize meanings in shared icon constants and feed desktop/mobile/header and action affordances from them. The existing `NAV_SECTION_ICON` already achieves this for several routes; Today, panels and notes remain duplicated.
- A blanket `wb_sunny` replacement is unsafe: the schedule FLOW occurrence is not Today, summary finish actions finalize a review, and “move to tomorrow” denotes another date. Make replacements by semantic use.
- Findings come from source/templates; no claim of a complete rendered-device or screen-reader pass. The contrast-test route is an internal design specimen, so its `home`, `favorite`, `settings`, `delete`, `block` and `add` examples should be retained as examples rather than redesigned as product navigation.

### Accessibility and implementation notes from this area

- Icons need an accessible **action** name on the interactive element, not just a ligature or status noun. Strong current examples: focus/break controls explicitly distinguish session versus break; Recently Deleted and idle allocation controls have labels.
- Concrete gap: attachment preview/open/copy/edit/remove controls are icon-only with no tooltip or explicit accessible name in `src/app/features/tasks/task-attachment/task-attachment-list/task-attachment-list.component.html:45`. Focus chooser create button similarly lacks a name in `src/app/features/focus-mode/focus-mode-task-selector/focus-mode-task-selector.component.html:18`.
- Existing `title` on task hover controls does provide native hint/name fallback; prefer explicit translated `aria-label` plus tooltip for consistent touch/keyboard use. Do not report these as wholly unnamed.
- Priority indicator already exposes translated low/medium/high labels and the numeric preset exists; preserve that accessibility during consolidation.
- Preserve user-selected project/tag/counter icons and plugin-provided identities. Change product defaults and fallback rendering, not saved user choices in bulk.
- Some dynamic icons differ from static template extraction: priority presets, recurrence quick settings, focus mode options, attachment types, `showScheduleIcon`, `toggleButtonIcon`, idle `confirmIcon`, and user custom counters are explicitly included above. ## Edit sequence and verification

1. Fix shared meaning first: Today/date shortcuts, date-grid marker, notes, scheduling/reminder/deadline mapping, import/export/copy, and delete/archive distinctions. Update every surface listed for that action, including mobile, native shortcuts and onboarding examples.
2. Extend the existing shared icon constants where a meaning repeats. Keep identity, command and state separate: a tracking category may use a timer while its Start/Pause buttons use play/pause. Preserve explicit custom user choices; investigate a narrow legacy-default presentation mapping before changing existing Today state.
3. Apply P2 navigation/category refinements as one consistent pass. A standalone replacement in the sidebar while settings/onboarding use the old symbol creates another inconsistency. No extra settings or icon library is needed.
4. Regenerate bundled plugin and native image artifacts through their owning build scripts when their source changes. Font-name replacements do not update inline SVG paths, Android vectors or iOS SF Symbols.
5. Verify desktop and narrow mobile at normal size; dark/light themes; keyboard focus; touch activation; translated labels; screen-reader accessible name/state; and font loading. Check start/pause/stop/reset, source/preview, scheduled/unscheduled/reminded, complete/incomplete, deleted/recoverable/permanent, and sync idle/busy/offline/error/disabled pairs. Run the repository's relevant checks after implementing changes.

For recognition testing, show the highest-frequency symbols with their real labels to someone unfamiliar with Ultra Tasks. Ask what each control does before they activate it. Keep text when participants cannot distinguish the action reliably; replacing an ambiguous pictogram with another ambiguous pictogram does not establish clarity.

## Reproduce the inventory

From the repository root:

```bash
python docs/research/icon-audit/scan.py . docs/research/icon-audit
node docs/research/icon-audit/build.mjs
```

The scanner is a bounded static extractor, not a TypeScript reachability analyzer. It retains dynamic/unverified registers instead of claiming those are resolved. The build step creates the recommendation catalog and self-contained HTML using this report, inventory JSON and existing bundled fonts/assets. Refresh the snapshot date/commit and recheck contextual recommendations whenever the underlying UI changes.

The follow-up [replacement approval report](icon-replacements.md) adds specific
before/after SVG candidates, a separate visual-identity pass, and review decisions.
Use it for the concrete choices; it records refinements to suggestions in this
initial semantic audit.
